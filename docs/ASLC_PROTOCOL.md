# ASLC — Audio Stream Link Codec: Wire Protocol (v1)

The byte contract between the **desktop node** (Windows/Linux, USB *host*) and the **Android
receiver** (USB *accessory*, per AOA). This is the single source of truth; both sides are
`AslcProtocol`/`AslcPayload` codecs kept locked by golden-byte conformance tests.

- Android reference impl: `app/src/main/kotlin/com/example/audiostreamer/usb/` (`AslcProtocol.kt`,
  `AslcPayload.kt`, `PcmFormat.kt`, `PcmCapabilities.kt`, `UsbPcmReceiver.kt`).
- Rust reference impl: this crate (`src/frame.rs`, `src/payload.rs`, `src/format.rs`,
  `src/capabilities.rs`, `src/receiver.rs`).
- Golden bytes: `testdata/aslc_golden.hex`, generated by the Android `AslcGoldenVectorGeneratorTest`
  (Android is the shipped source of truth). The Rust `tests/golden_vectors.rs` asserts byte equality.

## Transport

Runs over any **reliable, ordered, bidirectional byte pipe**. No magic/sync word and no packet
boundaries: framing is self-delimiting by the `payload_length` field, so a reader that always
consumes `12 + payload_length` bytes can never desync.

- Today on the desktop: TCP (dev/test). On Android: AOA bulk streams.
- The AOA handshake (USB control transfers + `WinUSB`) that *establishes* the pipe is a separate,
  lower layer and is **not** part of ASLC. It is documented and implemented at Milestone 1.

## Framing header (12 bytes, all Big-Endian)

| Off | Size | Field             | Notes |
|----:|-----:|-------------------|-------|
| 0   | 1    | `protocol_version`| currently `1` |
| 1   | 1    | `message_type`    | see below |
| 2   | 2    | `flags`           | `0` unless a message defines bits |
| 4   | 4    | `sequence`        | monotonic **per sender**, uint32 |
| 8   | 4    | `payload_length`  | uint32; `0..=262144` (`MAX_PAYLOAD`) |
| 12  | N    | `payload`         | `payload_length` bytes |

## Message types

| Value | Name            | Direction     | Purpose |
|------:|-----------------|---------------|---------|
| 0x01  | HELLO           | either        | greeting + version |
| 0x02  | CAPABILITIES    | device → host | advertised PCM set |
| 0x03  | CONFIGURE       | host → device | request ONE format |
| 0x04  | CONFIGURE_ACK   | device → host | granted format |
| 0x05  | START           | host → device | begin PCM_DATA |
| 0x06  | PCM_DATA        | host → device | PCM frames |
| 0x07  | STOP            | host → device | end stream |
| 0x08  | ERROR           | either        | protocol error |

**Initiator:** the Android *device* speaks first. On attach it sends `HELLO` + `CAPABILITIES`
unprompted; the desktop *host* does **not** need to send `HELLO` first. The host replies with
`CONFIGURE` and reads `CONFIGURE_ACK` before `START`.

## Error codes (in `ERROR`)

| Code | Name | Meaning |
|-----:|------|---------|
| 1 | VERSION_UNSUPPORTED | peer speaks a different protocol version |
| 2 | FORMAT_UNSUPPORTED | rate/depth/chan/encoding not offered or not renderable |
| 3 | FRAME_LENGTH_INVALID | `PCM_DATA` body ≠ `frameCount × bytesPerFrame` |
| 4 | MALFORMED_MESSAGE | payload unparseable |
| 5 | NOT_CONFIGURED | `START`/`PCM_DATA` before a successful `CONFIGURE` |
| 6 | PROTOCOL_SEQUENCE | duplicate `START`, `STOP` without stream, etc. |
| 7 | BUFFER_OVERFLOW | consumer could not drain |
| 8 | TRANSPORT_FAILURE | underlying pipe read/write failed |
| 9 | INTERNAL | catch-all |

All errors are **recoverable**: the receiver stays alive and accepts a re-`CONFIGURE`/re-`START`.

## Payload layouts

### HELLO
`u8 protocol_version, u8 role (0=host,1=device), UTF-8 role_tag (rest)`

### CAPABILITIES (device → host)
```
u8   sample_rate_count
u32  sample_rates[...]        // Hz, BE
u8   bit_depth_count
u8   bit_depths[...]
u8   channel_count
u8   channels[...]
u8   encoding_count
u8   encodings[...]           // ENCODING_PCM = 0x01
u32  max_frame_bytes          // largest single PCM_DATA payload accepted
u32  recommended_buffer_bytes // receiver's preferred sink buffer
u32  capability_flags         // reserved, 0 today
```
Android advertises `{44100,48000,88200,96000,176400,192000} × {16,24,32} × {1,2}`, encoding PCM,
`max_frame_bytes = 16384` — **narrowed at runtime** to what that device can actually render
(`AudioTrack.getMinBufferSize`). **Only `CONFIGURE` a format present in the received set.**

### CONFIGURE (host → device)
`u32 sample_rate, u8 bit_depth, u8 channels, u8 encoding(=0x01), u8 reserved(=0), u32 flags(=0)` (12 bytes)

### CONFIGURE_ACK (device → host)
`<CONFIGURE 12 bytes echo>, u32 bytes_per_frame, u32 max_frame_bytes` (20 bytes)
The host MUST verify `bytes_per_frame` equals its own computed frame size, else treat as failure.

### PCM_DATA (host → device)
`u32 frame_count` followed by exactly `frame_count × bytes_per_frame` raw PCM bytes.
A body-length mismatch is rejected as `FRAME_LENGTH_INVALID`. Each payload SHOULD stay ≤ the
negotiated `max_frame_bytes`.

### STOP / START
Empty payload.

### ERROR (either)
`u16 error_code, u8 offending_message_type, u8 reserved(=0), UTF-8 message (rest)`

## PCM sample format

- **signed little-endian, interleaved** (matches Android's native byte order).
- `bytes_per_sample = bit_depth / 8` → 16 = 2, **24 = 3 (packed, NOT 24-in-32)**, 32 = 4-byte int (not float).
- `bytes_per_frame = bytes_per_sample × channels`.
- Transparent only: no resample, no codec substitution. Unsupported `CONFIGURE` → `FORMAT_UNSUPPORTED`.

## We do NOT claim bit-perfect

The desktop sends unmodified PCM frames; whether the phone's output path is bit-exact end-to-end
(incl. Android AudioFlinger and the physical DAC) is outside this protocol's guarantee. The contract
is "these bytes are the samples, as negotiated." Nothing more.
